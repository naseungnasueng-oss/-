# ROOM1 현재 기능 스펙

브랜치: `integration/room1-5-shared`. 최신 사용자 확정 범위는 [ROOM1_QA_REVISION.md](ROOM1_QA_REVISION.md), 공용 동작은 [공용 스냅샷](SHARED_CURRENT_SNAPSHOT.md)을 참조한다. 아래는 현재 소스 기준이며 기존 웹 ZIP에 자동 반영된 것은 아니다.

## 화면 안내

- 별도로 뜨는 결과 메시지와 하단 호버 힌트 바를 숨긴다. 휴대폰 문자·갤러리, 문서 이미지, 키패드 입력값과 성공 화면은 유지한다.
- 핫스팟 강조는 완전 투명하되 클릭 판정은 유지한다. 다른 방의 공용 박스 스킨 표시는 바꾸지 않는다.
- 방 이름 태그·돋보기 UI는 계속 숨긴다. 문 화면의 잠금/잠금 해제 상태 표시 영역도 숨긴다.

- 추가 QA 조정: 전체 화면의 책상 쪽 왼쪽 진입 영역을 `(0,250,580,700)`으로 넓혔다(1536×1024 기준). 문·휴대폰 영역과는 겹치지 않는다.
- 공용 타이머의 남은 시간 바는 `RoomTimerSettings.redBarColor=(0.52,0,0.01,1)`로 더 선명하게 표시한다. 시간 계산·바의 시작/진행 위치는 유지하고, 표시 갱신 시 설정 색을 다시 적용한다. 회색 패널은 알파 0으로 투명하게 하며 숫자·게이지·캐릭터는 유지한다. 실제 색감은 화면 QA 필요.

## 휴대폰

- 바닥 휴대폰 클릭 즉시 현장 휴대폰 UI를 연다. 사용/획득/취소 선택창과 획득 동작은 없다.
- `OpenPhone()`도 현장 사용으로 연결한다. 휴대폰은 바닥에 계속 남으며 인벤토리에 추가하지 않는다.
- 비밀번호 입력창은 휴대폰 본체의 가로 중앙에 정렬한다. 비밀번호 `5711`은 네 번째 숫자 입력 즉시 자동 판정하며 `#` 입력을 요구하지 않는다. 맞으면 홈으로 이동한다. 틀리면 입력창에 빨간 **입력 오류**를 표시하고 저장된 입력을 비운다. 다음 숫자부터 정상 표시로 다시 입력한다. 네 자리 미만의 `#` 입력은 무시한다.
- 해제 후 홈에서 문자·갤러리를 열고, **홈** 버튼으로 돌아온다.
- 휴대폰은 방 화면과 이동 이력에 영향을 주지 않는 오버레이다. 바깥 클릭으로 닫되 뒤쪽 사물을 동시에 작동시키지 않는다.

## 책상·좌우 서랍·획득

- 좌우 서랍은 독립적으로 열고 닫는다. 열린 서랍의 닫기 클릭 영역은 유지하되 **서랍 닫기** 글자는 표시하지 않는다.
- USB·사진 조각은 클릭 즉시 한 번만 획득한다. 조사/획득/취소 선택창은 없다.
- 성공적으로 획득했을 때만 해당 아이템과 아이템 클릭 영역이 사라진다. 인벤토리가 가득 차면 현장 아이템은 남는다.
- 획득 후에도 빈 서랍을 닫고 다시 열 수 있다. 열림 상태와 획득 완료 상태는 별개이며, 다시 열거나 인벤토리에서 아이템을 제거해도 현장에 재생성하지 않는다.
- 방을 이동해도 서랍 상태를 유지한다. 한쪽 조작은 다른 쪽에 영향을 주지 않는다.

## 신문

- 책상의 신문은 현장 읽기 전용이며 획득하지 않는다.
- 신문 화면에서는 뒤로 버튼을 숨긴다. **신문 종이 바깥 클릭 → 책상 복귀**, 종이 안 클릭은 화면을 유지한다.
- 기존 신문+책상 이미지의 종이 외곽을 기준으로 판정한다. 돌아가는 클릭이 책상 사물까지 작동시키지 않는다.
- 인벤토리의 클릭 우선권/입력 소비 규칙은 유지한다.

## 문과 성공 화면

- 문 비밀번호는 `736`. 정답 후 공용 해제 대기 시간(기본 1초) 동안 방 UI 입력을 막은 뒤 성공 화면 진입을 시도한다.
- **문 잠금 해제 + USB 소유 + 사진 조각 소유** 조건은 유지한다. 신문 읽기나 휴대폰 소유를 새 조건으로 추가하지 않는다.
- 아이템이 부족하면 자동 성공 처리하지 않는다. 나중에 아이템을 챙긴 뒤 문을 사용해 성공 화면에 들어갈 수 있다. ROOM1의 별도 결과 메시지는 숨김 상태다.
- 성공 화면에서 인벤토리를 닫되 공유 타이머는 계속 흐른다. **2번 방으로** 버튼으로 다음 씬에 이동한다. 잠금 해제 자체가 ROOM2를 직접 로드하지 않는다.
- 시간이 만료되면 성공 화면 진입 및 다음 방 이동을 허용하지 않는다.

## 공용 인벤토리 변경

- 2열 × 6행, 12칸. 패널 기준 크기 250×700.
- 최초 열기만 화면 우하단 여백 안쪽에 배치한다. 이후에는 이동한 위치를 보존하며 닫기/다시 열기/방 이동으로 초기화하지 않는다.
- 표시 시 화면 밖으로 나간 좌표는 보이는 영역으로 보정한다. 위치 기억은 현재 실행 세션 범위이며 저장/재실행 복원은 구현하지 않았다.

## 검증과 남은 QA

- Unity 6000.3.23f1 응답 파일을 이용한 런타임/에디터 직접 C# 컴파일 통과, 임시 컴파일 출력 제거.
- `Room1BatchSmokeTest`를 새 계약에 맞춰 수정했다: 12칸·최초 위치/재열기, 직접 획득, 현장 휴대폰, 신문 왕복, 빈 서랍 닫기, 숨긴 UI, 실제 대기 후 성공 화면 유지. **이번 개정 테스트는 아직 실행하지 않았다.** 사용 중인 Unity 에디터를 닫거나 중단하지 않았다.
- 실제 포인터로 신문 외곽, 서랍 아이템과 문 클릭의 겹침, 인벤토리 드래그/위치 기억, 필수 아이템 부족·시간 만료 시 진입 차단을 확인해야 한다.
- 12칸으로 줄어든 인벤토리의 전체 ROOM1→5 수용량도 QA 필요. 아이템을 임의로 삭제해 공간을 만들지 않는다.
- 원본 이미지/다른 방 정책은 유지했다. 대체 `Room1PrototypeUI`를 현재 이미지 UI와 같은 전체 UX로 맞춘 것은 아니다.
